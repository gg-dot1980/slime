# OCR Grow 精簡續跑流程

版本 v1 · 2026-11-26（台灣時間）。適用已授權的 `feat/grow-evaluation-20261125` Grow 研究；目標是減少重讀、重複調查及無新證據的改版。這是工作方式調整，不修改 runner、遊戲、驗收、既有批准或正式 OCR4 規格。

## 固定研究條件

使用原遊戲同源 iframe、可見畫面／HUD／玩家輸入及既定桌機幾何。v2.13 與 v2.22 各固定 4 局探索，兩版各至少 2 勝且資料完整，才以同一凍結候選各另起 12 局獨立確認；每版至少 6 勝，每勝須在 150 遊戲秒內達體型 200 並有可見成功結算。各幾何分組，探索與確認不混用。依[既有批次入口](repro/grow-local-r4-20261126/README.md)執行，所有開局、死亡、逾時、中止與未知均保留。

## 下一個凍結候選的手機模擬組

Grow50 封帳後，下一個新凍結的候選須另跑手機直向搖桿探索。沿用同一策略來源，v2.13 與 v2.22 各固定 4 局。即使桌機探索未達門檻，手機組也要跑完；已啟動的桌機獨立確認優先。桌機和手機依序使用瀏覽器。依[手機搖桿測試入口](repro/grow-mobile-joystick/README.md)啟動本機 Chromium 觸控模式，外窗 402×753、畫布 384×467、DPR 1，透過搖桿與第二觸點加速操作。按遊戲版列出開始、完成、過關、死亡、截止、中止及未知，附勝／局與百分比。正式手機樣本從該候選凍結後起算。手機組僅統計探索勝率，原桌機獨立確認照既定門檻執行。

## 每次接續的工作方式

1. **先讀短檢查點。** 由 [GROW-CHECKPOINT](GROW-CHECKPOINT.md) 找當前候選、凍結來源、批次狀態和唯一下一步；比對遠端變更與現有 ledger。只補讀相關差異及有變更的適用指示。完整私人證據／還原包作備援，缺檔、環境遺失或特定追查需要時才讀取；不每次重新解包、重建或掃全部歷史。
2. **先接續已啟動批次。** 核對實際程序與 ledger；排程顯示執行中不能單獨證明程序仍活著。已有批次時不重開同一場次；確認已啟動時先完成或如實記錄其中止，不能另開候選取代。
3. **每次聚焦一個候選。** 每次續跑最多新建一個候選；已有待完成候選時本次不新建。已凍結候選完成既定批次與存檔前不再改版。新候選只驗證一個有證據的假說，先記失敗現象、修改範圍、預期觀察及判定依據。未見改善且沒有新證據時先留下結論，不連續試猜參數。
4. **批次交給既有工具。** 由 runner 連跑、分類、統計與匯出；模型不逐局重新開局或手算勝率。需要確認進度時只讀短 status，正常等待期間不反覆分析相同內容；在批次完成、錯誤或新證據需要決策時介入。
5. **先讀 summary。** 先看各版完整分母、結果、時間／體型和異常，再依假說讀必要的日誌片段或代表性畫面。完整原始證據仍保存，不把整批逐秒資料直接載入每輪模型上下文。
6. **重用已核對成果。** 相同來源與環境的有效檢查不無故重跑；依 diff 執行受影響的檢查。新策略的探索、獨立確認及要求的獨立核對仍須完成，不能沿用舊候選結果充數。純說明、索引或檢查點更新不重跑遊戲。
7. **相同阻礙不重複調查。** 記錄錯誤、環境／來源指紋、已試修復與下一個可執行動作；後續沒有條件變更或新證據時，不重新下載、重建整套環境或重做同樣失敗。保留明確 blocker，不能以未知冒充成功。
8. **委派限定範圍。** 需要獨立核對或確有獨立工作才委派，提供自足的短任務與必要檔案／證據，避免整段研究歷史複製給多個代理。保留要求的獨立驗證；不為省用量取消它。
9. **保存與推送照常。** 每個實質策略版本，包括失敗／中止版本，依已授權流程立即推 GitHub 並驗證；結果可後續提交。原始逐局紀錄、還原包與影像私人保存，公開只放程式、允許的彙總與來源。此流程不授權 GitHub Actions、實體手機測試或網站部署。
10. **交接只寫增量。** 每階段完成後更新短檢查點：候選／來源、各版局數與狀態、證據入口、阻礙及唯一下一步；保留歷史結果於既有逐版入口。日常回報以 4–8 行列新增結果、分母、結論、下一步和 commit。可記新增候選／測試批次／重跑原因等流程指標；未取得真實用量時不換算 token、費用或剩餘額度，也不承諾額度耗盡後環境仍持續執行。
