# OCR4 規格

規格版本：v1.1；核對日期：2026-11-19（台灣時間）。唯一權威：`gg-dot1980/slime` 的 `test/ocr-test`。接手請明示 repo / branch / base commit，先讀 [存放規則](GITHUB-STORAGE.md) 與 [交接索引](TEST-HANDOFF.md)。這是現行要求整理，不是驗收通過聲明。

## 目標及範圍

- 影像辨識操作；以畫面、可見 HUD 與受支援輸入進行測試，不把遊戲內部隱藏狀態作控制器輸入。
- 桌機：v2.13 起至目前所有實際受支援版本，**每個版本分別在 2:30（150 秒）內過關率至少 50%**；不能用跨版本合計掩蓋個別未達標。
- 手機依使用者最新決定跳過，紀錄標「跳過」，不是通過；桌機縮小視野不算真實手機。
- 只認本局可見結算勝負及遊戲耗時。截尾、未完成及中止不得冒充死亡或過關；分開報告所有開局、勝利、死亡、逾時、中止、未知及其分母。不能用牆鐘或離線預測代替遊戲結果。
- 少量局、固定種子、離線回放、合成或診斷結果不能直接宣稱正式勝率；報告樣本限制，不保證長期成功比例。

## 固定測試條件

每批開始前凍結控制器 source commit／hash、遊戲 snapshot／版本、A/B 定義、預定局數／順序、停止條件與判定規則；局中不換版、不事後挑選成功樣本或刪除失敗。保留完整開局與異常紀錄，確認停止釋放按鍵。具體試驗的資源和逾時保護按該批 protocol，不能將工程診斷門檻自行升格為使用者驗收。

| 項目 | 現行狀態 |
|---|---|
| 正式批次每版本樣本量、獨立確認局數／統計準則 | TBD；須在下一正式批次前明定，不直接套用歷史局數 |
| 正式桌機 OS／硬體／瀏覽器與版本、視野、DPR、執行方式 | 統一設定 TBD；每批必須具體記錄，真機／模擬分開 |
| 近期可重現診斷參考（非全域驗收設定） | r227：Linux 桌機 Chrome156、DPR1、遊戲畫布及 CSS2000×1163、v2.20；見逐版紀錄限制 |
| 隨機性 | 每批記錄 seed 是否存在；未記則未知。不可保證相同隨機結果，不能依結果換 seed |
| 含中止／未知時的正式勝率分母與補跑政策 | TBD；必須事前明列，未定前不得聲稱完成正式驗收 |
| 資源使用 | 受管共用預覽須確認空閒及可復原；不擅自停其他工作或另架服務 |

## 成果保存與發布分離

每個可交接輪次依 [GITHUB-STORAGE v1](GITHUB-STORAGE.md) 建立 `docs/ocr/repro/<輪次>/` 入口，保存可公開原始碼、設定、腳本、無像素結果及限制，更新 [TEST-HANDOFF](TEST-HANDOFF.md)。缺少材料標未補／未驗證；影像只留獲准的本機，不上傳 GitHub。這份規格不改寫歷史批次結果。

GitHub 測試記錄與已授權的 /ocr-test 小改版同步，是測試流程；它們不代表 OCR4 驗收或部署。OCR4 必須達到上述各版本桌機條件才可發布 /ocr4 並更新索引，仍須遵循當次部署授權及工具核准。本次文件變更不部署任何頁面、不變更 main 的遊戲程式。

## v1.1 測試頁與正式發布分流

依使用者最新授權，`/ocr-test` 是展示實驗的地方，可在正式勝率驗收前按計畫同步 GitHub `test/ocr-test` 與線上測試頁；頁底新到舊記錄變更、原因、實跑或回放結果、採用狀態與尚未驗收。負面結果及診斷不得更換公開預設策略。每次須核對基本載入、同版讀回與正式頁未變；無法隔離或權限不足，明列待同步。

`/ocr` 索引及其正式頁面（包括 `/ocr3`、`/ocr4`）仍須通過對應驗收才可更新。不得連帶修改其他路由、正式資料庫或排行榜。此分流不改 150 秒／50% 門檻、不改歷史結果，也不授權上傳影像。
