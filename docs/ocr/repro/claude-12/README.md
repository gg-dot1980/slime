## 結論

1. **claude-12：0/18 過關，沒有比 claude-11 好。**
   - v2.13：9/9 撐到 150 秒，體型 51～127，中位 79。
   - v2.22：4/9 死亡，存活局 77～132，中位約 111。claude-11 是 1/6 死亡、中位約 130。
2. **累計**：v2.13 與 v2.22 各 67 局 OCR 控制器（所有候選合計），150 秒內過關 0；最佳體型 151（v2.13）、160（v2.22）。
3. **最重要的發現**：受限全知機器人等於辨識完全正確、只用畫面和小地圖資訊的控制器，它在 v2.13 是 0/9、在 v2.22 是 2/9。**就算辨識完美，目前這套決策規則也達不到每版 50%。** 控制器辨識的主要缺口已經補上，現在的瓶頸是決策策略本身。

## claude-12 的改法（claude-11 加上兩項）

claude-11 的兩次死亡，凶手都是 1.12 倍的 NPC：

- **v2.22**：小地圖上 ≤1.12 倍是白點，其中包含 1.08～1.12 倍的致命範圍。凶手剛好 1.12 倍，被邊緣裁切後套用了「裁切物件＋白點＝目標」的規則。邊緣推算的半徑（1.22R）其實已判為危險，但白點規則先執行。
  - **改法（`segFirst`）**：有推算值時以推算值為準；推算 >0.8R，或可見半徑就已經 ≥0.8R 的，不套用白點規則。
- **v2.13**：凶手完全在畫面內，半徑 107，但最後幾次決策中從偵測結果消失。推測是和玩家的色塊黏在一起，被「排除玩家本身」的過濾一起移除。
  - **改法（`memory`）**：600px 內的致命物件如果消失，用最後速度外推，保留 0.6 秒。

## 建議的下一步

- **先改進決策策略，再接到控制器**：用受限全知機器人當開發平台，它沒有辨識誤差，迭代快，也最接近控制器能拿到的資訊。目標是在 v2.13 和 v2.22 都達到 ≥50%，再把同樣的決策移到 OCR 控制器上。
- **可以先試的方向**：
  - 更長的預測時間（目前 1.5 秒）。
  - 考慮被包圍時要留逃生路線，例如偏好離牆、離 NPC 群較遠的區域。
  - 前期優先找獵物。
- **v2.13 的完整全知機器人也只有 1/3**：v2.13 的 50% 目標可能本身就非常困難，需要更多局數評估。
- 依使用者要求不改既有檔案，所以沒有更新 `TEST-HANDOFF.md`。
