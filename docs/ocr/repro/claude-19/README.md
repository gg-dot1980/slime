# claude-19、控制器例外修正、claude-11 對照重跑（v2.13 與最新版 v2.22）

2026-11-25（台灣時間）。分支 `ocr-claude`，接續 [claude-18](../claude-18/README.md)（9382cda）。全部為新檔案，或只改本分支新增的檔案。不是 OCR4 驗收。

## 結論

1. **修正一個會讓控制器中途停下的錯誤**（影響 claude-15～19）：
   - `rememberStrokeDots` 直接讀 `map.player.x`，但小地圖上偶爾找不到玩家點（`map.player` 為 null），這時會拋出 `Cannot read properties of undefined (reading 'x')`。控制器的一拍出錯時會呼叫 `stop(false)` 並暫停遊戲。
   - claude-19 第一次批次因此出現 3 次 `wall-timeout`；加入偵測後的第二次批次，v2.22 有 2 次 `controller-error`。先前混合版 `detview` 的那次例外也是同一個原因。
   - 修正後函式在 `map.player` 不存在時直接回傳原本的標記，並新增 1 項合成檢查（共 80 項）。
   - claude-16～18 的批次中沒有出現 `wall-timeout`，但當時的批次腳本還不會偵測這種停頓。
2. **批次腳本新增 `controller-error` 判定**：遊戲時間連續 10 秒沒有前進、又沒有結算時，記下狀態欄文字（例外訊息）、動作和死前決策。`wall-timeout` 時也會記下狀態。
3. **claude-19**（claude-11 加上 segFirst、lethal memory、點大小、尺寸記憶、合併碎片，沒有 v2 規則），修正後重跑 0/12：
   - v2.13：63、66、58、54、62、42。
   - v2.22：死139/54、56、145、36、82、死55/44。
4. **claude-11 對照重跑**（同樣的環境，在 claude-19 之後執行）：
   - v2.13：59、70、75、95、136、85，中位約 80；原本 6 局中位約 95。
   - v2.22：59、142、死95/182、死72/70、103、69，存活局中位約 86；原本約 130。
   - **同一個策略重跑，中位數就差了 15～45。** 每組 6 局分不出候選之間大部分的差異；最近幾輪「沒有改善」的判斷，很多也無法下定論。

## 對之後測試的影響

- **增加局數**：要比較候選，每組至少 15～20 局，或使用成對設計：同一時段交錯跑兩個候選，並報告中位數的信賴區間。
- **混合版的發現仍然有效**：辨識完美時，每局吞 NPC 增加約 60%。這是大幅度的差異，不是雜訊。v2.13 小地圖上致命白點只認出 5/194，也是明確的量測結果。
- **要達成目標需要大幅改善**：目前真實控制器在 150 秒時多在 50～150 之間，要穩定長到 200，需要的是大幅度的辨識改善，不是微調。

- Linux 6.18（雲端），Chrome for Testing 153.0.8010.12 headless，Playwright 1.63.0，Node 22.23.5，視窗 2000×1163，DPR1，視野「標準」。
- 每次兩批同時跑，各 6 局，順序固定，不補跑、不刪除，無 seed。
- `games-noimages.jsonl` 包含 claude-19 修正後的 12 局、claude-11 對照 12 局，以及 1 局觀察器重現測試（`stall`）。修正前那兩次不完整的 claude-19 批次沒有保存。
