# Grow48 邊緣定位與遮擋取證

Grow48 的原 QHD 探索維持 v2.13 2/4、v2.22 1/4。這次使用既有 v2.22 診斷局的原畫布作對照。該局存活至截止。65 張已保存原圖中，有 28 張可與單次決策、HUD 和時間戳完全配對。以凍結 HTML 重跑靜態偵測，1,329 筆物件觀測的 13 個欄位逐一吻合，其中包括調整縮圖取樣方法時未使用的 25 張。

| 畫面狀況 | 觀察 | 可支持的結論 |
|---|---|---|
| 大型 NPC 靠近畫布上緣 | 在同一隻 NPC 的 17 張連續畫面中，17 張都留下裁切物件。16 張可讀完整名稱，偵測中心與名稱中心的偏差從 4.05 增至 77.62 個原畫布像素，主要在垂直方向。 | 物件仍被找到，回報位置隨裁切而向畫面內偏移。第 17 張的名稱也被裁切，不納入誤差。 |
| 兩個相互重疊的紫色 NPC | 同一次相遇的 4 張配對圖上，從兩個可分辨身體內部取出的像素都進入同一個連通色塊，每次只輸出一個 NPC。其中一張的輪廓擬合信心仍達 0.945。 | 合併發生在色塊分割階段，單靠提高輪廓信心門檻無法可靠篩出。 |
| 玩家遮住藍色獵物的一部分 | 藍色獵物的名稱與偵測中心相差 0.25 像素，同幀另一隻較大 NPC 相差 1.26 像素。原決策追向藍色獵物，後續可見 HUD 從 167 升至 178。 | 這是應保留的安全捕食對照。單幀無法確定實際吞食時刻。 |

新診斷在啟動前已固定 Grow48、原版 Git 遊戲、QHD 幾何、v2.13 與 v2.22 各一局及保存範圍。既有 runner 取得鎖、啟用本地服務並核對來源；Chromium 啟動器找不到執行檔，在建立頁面前結束。官方安裝來源在此環境回應 HTTP 403。兩版皆為 **已開 0／預定 1、結算 0**，未取得新畫面；此嘗試保存在私人紀錄。Grow46 既有確認仍為 v2.13 10/12、v2.22 4/12。以上三種畫面均取自存活局，先前死亡局缺少可配對的逐幀原圖。

下一步只驗證一項 v2.22 修改：能否用仍可見的輪廓修正單邊裁切大型 NPC 的中心。應在其他方向的裁切樣本、既有安全捕食與多物件重疊的反例上核對，再判斷是否值得凍結進入自然探索。逐幀原始資料、額外取樣位置與影像仍為私人檔案。
