# Grow48 末段可見畫面診斷

Grow48 原探索保持 v2.13 2/4、v2.22 1/4。三局 v2.22 死亡中有兩局的末筆預測間距為正。這兩局的控制器末段分別留存 23、25 筆數值決策，私人保存資料裡沒有可對應的原始畫面。末筆離玩家最近的主畫面 NPC 中心分別約 312、541 世界單位；小地圖兩種紅點辨識合併後，最近的紅點分別約 1,063、414 世界單位。這些是畫面辨識器輸出，無法單獨確認吞食者身分或證明當時畫面沒有貼身 NPC。

## 取證條件

只為補足末段原圖，預先固定一組終場診斷，沿用 Grow48 的相同完整 HTML、原始 Git 遊戲檔、QHD 原畫布與可見控制。由 r4 診斷依序各開 v2.13、v2.22 一局，沿用 150 遊戲秒限時、結算與釋鍵。執行前兩版診斷開局均為 0。此組有獨立的診斷協定識別與帳本，不進入探索或確認分母，也不替換先前任何一局。

臨時診斷目錄由原 r4 校驗後產生。診斷在自然結算或截止時停止。v2.22 的額外觀察器於決策回呼同一個 JavaScript 工作內複製原生可見畫布，另取結算動畫及面板出現時的畫布；HUD、畫布尺寸、時間戳與 PNG 雜湊另記於私人目錄。編碼忙碌時保留原控制節奏並記錄缺幀。私人還原保存首幀、每 15 秒代表幀、最後 5 秒的已擷取決策幀及終場幀。像素不送入控制器或 r4 數值帳本。觀察可能影響效能，另列樣本與實測覆蓋。

在研究 checkout 使用 Python、Playwright、Node 及既有 Chromium 執行下列命令。輸出目錄使用全新私有路徑，鎖檔與既有自然測試共用。若已有本組帳本，先讀帳本與狀態。

```bash
python docs/ocr/repro/grow-48-public/diagnostics/terminal-pair.py \
  --browser "$CHROMIUM_BIN" --out "$PRIVATE_TERMINAL_DIR" --lock "$NATURAL_LOCK"
```

[自然探索與歷次回放](natural.md) · [診斷驅動](../diagnostics/terminal-pair.py) · [可見畫布觀察器](../diagnostics/terminal-observer.js)

第一次載入時，診斷協定名稱與頁面預期的名稱不同，兩版均為 0 次開局。已保留該次傳輸紀錄，讓診斷頁核對預先指定的完整協定名稱及候選選項，再啟動原定的一組取證。

第二次已完成兩版載入預檢，建立批次時因臨時目錄缺少原 Node 套件設定而停止，兩版仍為 0 次開局。診斷目錄補入原設定，並讓專用協定名稱套用 r4 完整的文件來源與幾何稽核。兩次執行的啟動紀錄均保留。

## QHD 終場診斷結果

兩版均依計畫各開局、結束並釋鍵一次。兩次較早的載入停止均為 0 次開局。

| 遊戲 | 150 秒內達體型 200 | 可見結果 |
|---|---:|---|
| v2.13 | 1/1 | 成功面板顯示達到 200，遊玩時間 2:12。最後一次一般 HUD 顯示 192。 |
| v2.22 | 0/1 | 截止讀到體型 184。原計時器顯示已過 151 秒時，runner 依規定停止。 |

v2.22 的 1,502 次決策有 1,436 張原畫布，66 次因編碼忙碌而略過。159 筆不重複的定期與末段數值決策中有 150 筆能對上原圖、時間與 HUD，其中包括結束前保留下來的全部 17 筆末段決策。這局在截止前仍存活，先前兩局死亡時的吞食者身分仍未知。

在本局找出一段成長停滯，再以同局稍後一次追近並成長的片段對照。兩段是看過結果後選出的觀察樣本。

| v2.22 片段 | 可見行為 | 凍結規劃器的替代路徑 |
|---|---|---|
| 第 70–81 秒，體型維持 86 | 12 筆定期取樣中有 11 筆選了半徑約 42–43 的獵物。第 70、75、81 秒原圖均見粉紅色、同名稱的 NPC 在上牆旁，玩家與所選獵物的首末距離約 493、520。 | 7/12 筆有不同首方向可吃到其他食物或 NPC，且預測成長更高。其中 4/12 筆最低威脅間距也相同或更大，2/12 筆同時保有原路徑的最低牆距。 |
| 第 88–91 秒，追近後成長 | 4/4 筆選了半徑約 74 的 NPC，距離從 923 持續縮短到 289。第 92 秒體型達 100。 | 1/4 筆也有兼顧兩種間距的高成長替代路徑。單憑出現可替代路徑就轉向，會打斷這段實際追近。 |

[路徑核對程式](replay-plateau.cjs)重現了兩段共 16/16 個原決策。每筆都檢查原有 64 條兩段路徑，替代路徑須在模擬中吃到其他可見食物或 NPC，且整條路徑未吃到當前目標。這項比較無法推算改向後的實際勝率。依事前規則私人留存 57 張原圖，另留分析所引用的補充畫面。Grow48 的正式探索仍為 2/4、1/4，獨立確認尚未開始。

## 舊局能否用追逐停滯辨別換向時機

凍結一項可見訊號，在 Grow47、Grow48 兩個完整探索批次的 v2.22 舊局逐一核對。沿用兩版既有的半徑與位置配對容差。至少連續四筆定期決策跨三秒、都能唯一配對同一個已選可吃 NPC、玩家體型沒有增加且沒有可見吃 NPC 提示、全程尚未近身，首末中心距離縮短不超過小地圖一個像素時，記一次提醒。同一次連續追逐只記首次。每個提醒再用該版凍結程式重現原決策，檢查其他首方向能否預測吃到不同目標、得到更多成長並維持原路徑的最低威脅間距與牆距。

| v2.22 樣本 | 出現停滯的局數 | 提醒次數 | 有更高成長、且有相同或更大最低威脅間距的提醒 |
|---|---:|---:|---:|
| Grow47 探索逾時 | 2/3 | 6 | 0/6 |
| Grow48 探索死亡 | 1/3 | 1 | 0/1 |
| 兩批探索的勝局 | 0/2 | 0 | 無提醒可核對 |
| 本次用來發現假說的 Grow48 診斷逾時 | 1/1 | 4 | 2/4，其中 1/4 也保有原最低牆距 |

兩批探索共 864 筆定期決策，含 68 個滿足三秒連續配對的觀察窗。勝局只有 4 個這樣的觀察窗。七次舊局提醒的原決策全部重現，均未出現兼顧成長與最低威脅間距的替代方向。這個訊號能抓到部分追逐停滯，目前不足以凍結自動換向候選。這項核對新增自然開局 0。[可見停滯核對程式](check-chase-progress.py) · [替代路徑核對程式](replay-plateau.cjs)

另查這 7 次舊局提醒前後各相鄰一筆的定期決策，只納入仍可唯一配對同一所選獵物的樣本。逾時組在提醒前 1/6 筆、提醒後 1/4 筆有同時保住威脅與牆距的高成長替代方向，兩筆皆屬同一局。死亡組在提醒前 0/1 筆、提醒後 0/1 筆符合。把時機前後移一筆仍沒有跨兩組的改向證據。
