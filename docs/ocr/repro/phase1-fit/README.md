# 階段 1a：裁切物件圓擬合（claude-20）vs claude-11

協議：[PROTOCOL.md](PROTOCOL.md)（開跑前固定）。2026-11-26（台灣時間），頁面建置自 0f2cde1 的 `src/ocr-claude.html`。

## 背景（v2.22 邊緣巨型 NPC 的辨識，取自 claude-11／claude-19 先前的抽樣）

畫面內真實致命、卻沒被比對到的 NPC，幾乎都是部分在畫面外。這類邊緣巨型 NPC 共 1075 次：

| 情況 | 次數 |
|---|---|
| 弓形推算正確（圓心誤差 < 0.3R） | 422（39%） |
| 沒有推算值（角落、UI 遮罩、兩個邊緣） | 338（31%） |
| 推算偏差大 | 164 |
| 完全沒偵測到 | 151 |

## 圓擬合

- 對被裁切的色塊，取邊界像素中「外側是別的顏色或背景」的點（排除螢幕邊緣和 UI 遮罩），用 Kåsa 代數法擬合圓，修剪兩次殘差大於 1.5 倍中位數的點。至少 12 點，且擬合直徑要 ≥ 邊界框長邊的 0.8 倍。
- **實測**（`fit-check-noimages.jsonl`，claude-11 各 1 局）：

| | v2.13 | v2.22 |
|---|---|---|
| 推算／擬合 都有、只有擬合、都沒有 | 58、35、6 | 69、59、8 |
| 弓形：圓心誤差／R 中位、半徑比中位 | 0.11、0.99 | 0.15、0.93 |
| 擬合：圓心誤差／R 中位、半徑比中位 | 0.15、0.93 | 0.17、0.86 |
| 致命卻被擬合估成 <0.82R | 0 | 4 |

- **claude-20 的規則**（依實測訂定）：有弓形推算就優先用，沒有才用擬合；估計半徑小於可見部分 0.95 倍的不採用；邊緣目標 6 個小地圖像素內不能有紅點。

## 結果（每策略每版 20 局）

| | claude-11 | claude-20 | 中位數差（11 − 20）[95% CI] |
|---|---|---|---|
| v2.13 體型中位 [95% CI] | 80 [72, 97] | 100 [92, 109] | −20 [−34, 2] |
| v2.22 體型中位 [95% CI] | 85.5 [73, 103] | 97 [87, 113] | −11.5 [−30, 9] |
| v2.13 過關／死亡 | 0／0 | 0／4 | |
| v2.22 過關／死亡 | 0／7 | 0／8（另 1 局排除） | |
| 致命看成安全（兩策略合計） | v2.13：1/1258 | v2.22：1/1413 | |

- **決定**：兩個信賴區間都含 0，依協議 **claude-20 不採用，維持 claude-11**。中位數的方向偏向 claude-20，v2.13 的區間接近排除 0。
- **排除的 1 局**：v2.22 的 claude-20 第 4 局，開局第 3 秒「計算逾時，已釋放控制並暫停」（`controller-stop`）。擬合在偵測器裡計算，兩個策略都會跑到，計算負擔相同。之後需要替擬合設計算量上限。
- claude-11 這次在 v2.13 是 80 [72, 97]，階段 0 是 71 [60, 95]，兩次一致。
