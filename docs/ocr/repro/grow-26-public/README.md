2026-11-26（Asia/Taipei）。候選準備完成；自然實戰 **0 開局、0 結果**，尚未採用、部署或驗收。原目標仍為桌機 v2.13 與核對後目前版本各自於 150 秒內達到體型 200，獨立確認每版至少 6/12；手機跳過。這不是涵蓋全部受支援版本的 OCR4 正式驗收。

## 固定來源與唯一策略改動

直接父版是 [Grow-24](../grow-24-public/README.md)，其單檔來源 commit 為 `5c57270575a344a910243cf9238ab6a64e7683d0`，HTML SHA256 為 `f276dd1b6dd340c142f00027adf2ddeefc394c74db772edf814cd6f9445f6347`。

[完整候選 HTML](ocr-grow26.html) SHA256：`7f6494c12a22d2e833fbec796196cef39c04157325c304e3961ec644652a2f33`；Git blob：`5f260f114ccbf2deabe322f3af6a7d28b0e5f449`。本候選的 source commit 待首次提交後補記。

原規劃器列舉第一方向 0.6 秒、第二方向 1.6 秒的 64 條路徑，卻只用 2.2 秒終點評估白點接近。每 100 ms 重新規劃時，第二方向可能一直只是預測；為了讓遠期終點接近白點，第一方向反而可能先離開白點。

Grow-26 只讓 `mapOnly` 白點使用第一段第 6 步（0.6 秒）的預測位置計算接近效用。策略識別為 `grow-26`，函式為 `planGrow26`。仍把白點當作偵察目的地，預估吞食／成長收益為 0；可見食物、已分類 NPC、64 條預測軌跡、避敵與牆界條件均沿用父版。原遊戲同源 iframe、原生響應式 CSS、辨識與停止控制保留。

沒有繼承 Grow-25 的 150–300 距離政策；275 的近點仍依 Grow-24 排除。本候選不是同時合併兩種改法。

## 回歸與反向代價

[check-scout-progress.cjs](check-scout-progress.cjs) 以 Node 的真實 `assert/strict` 執行 **40 組、242 個斷言**，兩段 inline script 亦完成語法解析。每版 20 組包含上述南北反例、1500 遠點、275 排除、寬視野、可見食物／NPC、主畫面危險、小地圖紅點、牆、stale、空圖／無圖，以及朝向／背向／側向慣性。

38 個可規劃案例各自核對全部 64 條路徑：預測位置、硬牆、離牆保留區、威脅間距、風險與食物／NPC 成長計算均與父版一致。這只證明數值模型的這些計算保留，不能證明辨識正確或實際碰撞安全。完整輸出見 [synthetic-results.json](synthetic-results.json)。

**保留的不利取捨：** 同樣 HUD 95／速度 300，北方有 600 距離白點（面積 20），東方 120 距離有半徑 13 的可見食物，無敵無近牆時，父版向北偵察，候選改向東取食。候選的局部預估成長為 0.455，但遠方白點的實際 NPC 收益未知；這可能延後較大成長機會。1500 遠點的方向在固定例中不變，接近效用則由約 0.3373 降至 0.07118。不能把方向修正或較高局部食物收益當成整局改善。

```sh
node docs/ocr/repro/grow-26-public/check-scout-progress.cjs
```

指令由完整 Git checkout 根目錄執行，只需 Node 標準庫；本次為 Linux／Node v24.22.3。固定案例沒有 RNG 或外部依賴。此命令不啟動瀏覽器或自然遊戲。
