# Grow46 v2.22 連續相反方向擺盪核對

本核對使用 Grow46 v2.22 獨立確認的 4 勝／8 死亡封存樣點，新增自然局 0。原始 ledger SHA-256 為 `9f82ee6f548a233170f9be285e345abea765a6d42aad89b43dbbaeacc49fe092`。

## 定義與結果

擺盪窗須有三個連續約一秒樣點，HUD 均未增加、皆為預測正成長的 `intercept-growth`，連續所選可吃 NPC 的原始半徑差不超過 15%。A→B 與 B→A 的方向差都至少 135°，第一與第三方向差不超過 45°。相近半徑只是目標連續性的代理，不能證明是同一隻 NPC；重疊三點窗各自保留。

共找到 5 個擺盪窗：死亡第 3 局 4 個、死亡第 11 局 1 個；4 個勝局、死亡第 4、5、6、7、8、12 局均為 0。5 個窗的下一筆可見 HUD 都沒有增加。

把逃生／恢復、正風險、牆距扣分或可見牆距小於 150 排除後，只剩 2 個可安全試算點。若禁止第二次折返、再保持中間方向一個樣點，1 點的目標投影距離變近，另 1 點變遠。

| 指標 | 結果 |
|---|---:|
| 擺盪窗 | 5 |
| 下一筆 HUD 增加 | 0/5 |
| 安全排除 | 3/5 |
| 可安全試算 | 2/5 |
| 保持中間方向後變近／變遠 | 1／1 |

## 決定

擺盪訊號集中於死亡局且沒有出現在勝局，但樣本只涵蓋死亡第 3、11 局，沒有涵蓋預定核對的第 6、7 局。安全試算也沒有一致改善，因此不建立新版本、不啟動自然探索。

下一步回到未被追逐效率解釋的死亡第 4、5 局，只核對死亡前最後三秒的大型 NPC 可見辨識、風險值與所選方向，確認是否有威脅已可見但沒有進入避險決策；不先修改。

重算程式：[oscillation-audit.py](oscillation-audit.py)。逐局原始資料與影像仍只保存在私人證據包。
