## 結論

- **在混合版上找到決策規則的平衡**（控制器決策函式＋畫面內完美辨識＋真實小地圖損失）：
  - **claude-15 規則**（claude-14＋v2 避牆避群）：12 局 0 死亡，但太保守。v2.13 體型只有 51～88，v2.22 是 80～183。
  - **claude-16 規則**（claude-15 拿掉 `safe` 的加重扣分，扣分方式和機器人 v3 相同）：**12 局 0 死亡，3 局過關**。v2.13 是 2/6（136、146 秒），v2.22 是 1/6（146 秒）。
- **真實控制器 claude-16**：0/12 過關。v2.13 體型 46～66（全活）；v2.22 是 68～111，1 局死亡。遠低於同規則的混合版。
- 所以決策規則在辨識正確時表現平衡，**剩下的差距在辨識**。

## 改動

- **claude-15**：claude-14 加上 v2 規則（2.5 秒預測、1.5 秒預測點的擁擠度扣分、小地圖換算的離牆距離），再加 `rememberStrokeDots`：小地圖點如果在視野框線 2.5 像素內消失，保留 1.5 秒。原因是視野框畫在點的上面，會蓋住剛好在畫面邊緣的 NPC。
- **claude-16**：claude-15 拿掉 `safe`，危險間距回到 40px，間距 <160 才扣 ×0.4。
- 合成檢查 72 項，其中框線點記憶 4 項。

## 差距排查

- **食物偵測不是問題**（`scripts/probe-food-ocr-claude.mjs`，v2.13，199 幀）：畫面內真實食物 1309、命中 1243，召回率約 95%；漏掉的多在離玩家 400px 以上。
- **畫面內 NPC 數量正常**：每幀約 1 個，偵測數和真實數相當。控制器的危險清單中位 15 個，主要來自畫面外的紅點，混合版也有同樣的紅點。
- **決策比對**：後悔值大的情況，主要是控制器在追畫面外的白點（hunt-map）。

## 下一步：逐項替換實驗

在混合版上一次只把一部分輸入換成控制器真正的辨識結果，找出拖累成長的部分：

1. **小地圖換成真實辨識**（紅點、白點、尺寸），畫面內維持真實狀態。
2. **畫面內換成真實辨識**（NPC 和食物），小地圖維持真實狀態。

哪一項替換造成成長大幅下降，就優先改善那一項辨識。
