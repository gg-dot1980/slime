## 1. 真實小地圖點大小的量測（[dotsize-probe.json](dotsize-probe.json)）

做法：
- claude-28、QHD 幾何，每版跑 140 秒。
- 控制器每次決策時產生的白點標記，都配對到 160 世界 px 內最近的真實 NPC。
- 工具：`scripts/probe-dotsize-qhd-ocr-claude.mjs`。

結果：

| | v2.13 | v2.22 |
|---|---|---|
| 估計大小／真實大小（真實 46～112 的點）p10／中位／p90 | 0.85／0.945／1.06 | 0.85／0.946／1.04 |
| 真實 46～112、≤0.909R 的獵物讀不出大小 | 238/707（34%） | 546/1505（36%） |
| 被當目標的白點中，真實吃不到（>R/1.08） | 107/652 | 166/1113 |
| 被當目標的白點中，真實是危險（≥1.08R） | 26/652 | 63/1113 |

- 估計值平均偏小約 5%。
- 被當目標的危險白點多半配對到半徑 200 的巨型 NPC，像是巨型 NPC 旁邊的點被讀成白點。

## 2. 候選

claude-28 加上：
- `whiteBias` 1.058：點大小估計除以 0.945。
- `whiteRedClear` 5：5 個小地圖 px 內有紅點或威脅的白點不當目標。

混合工具（3 倍速，每版 8 局，[hybrid-screening-summary.txt](hybrid-screening-summary.txt)）：
- `HYBRID_SRC=detall`（控制器完整的真實辨識）：claude-28 為 100／129.5，claude-29 為 126.5／126。
- `HYBRID_MAPNOISE`（模擬小地圖，加上上表的大小誤差與讀不出的比例）：claude-28 為 144.5／143.5。

模擬小地圖即使加了大小誤差也比真實小地圖好，所以真實小地圖還有其他差異：例如巨型 NPC 旁的點、紅點辨識、位置。

注意：`detall` 在 3 倍速下，控制器內以牆鐘計時的記憶（視野框記憶、危險記憶）會變成遊戲時間的 3 倍長，這組結果只供參考。
