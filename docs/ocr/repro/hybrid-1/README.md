# 隔離實驗：控制器決策函式＋完美辨識（v2.13 與最新版 v2.22）

2026-11-25（台灣時間）。分支 `ocr-claude`，接續 [claude-14](../claude-14/README.md)（d0689ea）。全部為新檔案，或只改本分支新增的檔案。不是 OCR 控制器，也不是驗收。

## 目的

claude-14 每局吞 NPC 的次數只有受限全知機器人的一半。要分清楚原因在辨識還是決策規則。

## 方法（`scripts/ocr-claude-hybrid.mjs`，測試專用）

- 用控制器自己的決策函式 `planClaude5`，選項同 claude-14。決策間隔 200ms，和控制器相同。
- 輸入改成從真實狀態建立的資訊，範圍限制在畫面與小地圖看得到的部分：
  - **畫面內**：所有 NPC 和食物的精確位置、半徑、速度，沒有裁切。
  - **小地圖**：畫面外大於 1.12R 的是紅點；其餘是白點，45.6～114 的附上尺寸。
- **`HYBRID_MAP=real`**：把真實小地圖的兩個損失加回去。位置四捨五入到小地圖像素（約 72 世界 px），視野框線 1.5 像素內的點刪除（視野框畫在點的上面）。
- 決策函式透過攔截的頁面回應，在記憶體中掛到 `window.__p5`，repo 檔案不變。

## 結論

1. **成長慢主要來自辨識，不是決策規則**：同一套決策規則換成完美辨識後，吞 NPC 次數從約 10.5～11 次增加到 16～18 次，接近機器人。
2. **辨識差距大約一半在小地圖、一半在畫面內**：
   - 小地圖的損失（位置量化、被視野框蓋掉）讓吞食次數少約 3 次。
   - 畫面內的辨識（尺寸估計、裁切、漏偵測、碎片）又少約 3 次。
3. **v2.22 的存活要靠決策規則**：完美辨識的混合版在 v2.22 死了 4/6，因為看得到更多獵物、變得更積極。機器人 v3 有避牆和擁擠度規則，12 局只死 1 局。將來的候選應該結合這些規則。

## 其他量測（`velocity-check-noimages.jsonl`，claude-14 各 1 局）

- **控制器對玩家速度的估計**：誤差中位 12～24 px/s，實際速度中位約 286 px/s。
- **畫面內未裁切 NPC 的速度估計**：誤差中位 13～21 px/s，p90 為 30～53 px/s；NPC 真實速度中位約 30 px/s。
- **畫面內真實獵物的分類**：v2.13 是 NPC 36、當成食物 5、沒偵測到 5；v2.22 是 19、2、4。小型 NPC 被當成食物不是主因。

## 下一步

- **畫面內辨識**：比較混合版和控制器在同樣局面下的決策差異，例如追獵目標的選擇、被碎片擋住的路線。優先處理出現次數最多的差異。
- **小地圖**：視野框線上的點無法直接讀到，只能靠畫面上露出的部分（已有邊緣弓形推算），或用前一刻的追蹤記憶補上。
- **決策規則**：在混合版上結合機器人 v3 的避牆和擁擠度規則，確認 v2.22 的死亡能降下來，再移植到控制器。
