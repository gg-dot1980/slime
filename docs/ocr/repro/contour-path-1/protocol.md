# contour-path-1 frozen protocol

Base: GitHub test/ocr-test 651ce8918080f1a693b9adcf6b3fd6e427606986; Sites166. No controller changes.
Hypothesis: same visible large contour across frames and shrinking path separation provides more specific early warning than snapshot brightness/heading.
Fixed development: new447–451. Fixed independent controls: success209229–232 and success161143–145. Keep every frame and clipped, merged/player-overlap, missing association and heading-change counterexample. No new games or browser use this stage.
Read only previously captured same-source Canvas PNG pixels. Decode offline with Node zlib, cross-check RGBA hashes independently with Pillow; this is NOT a new browser ImageData color-management equivalence test. Shared core accepts RGBA and could run from ImageData without hidden state.
Visible component: RGB max>=80, saturation>=0.25, 12 fixed hue bins, four-neighbor connectivity, area>=16 analysis pixels. These are visible colored surfaces, not verified NPC identities. Associate recorded NPC center to component at center or four offsets of0.25radius; require exactly one component; multiple recorded NPCs sharing it => merged unknown. No component or clipped edge or intersecting player disk => unknown. Never shrink original threat using this component.
Temporal pairing: mutual unique candidate within150 world-relative image pixels, circular hue difference<=30degrees, area ratio0.65–1.55. More than one candidate => ambiguous. Require3 consecutive associated frames (two transitions), with>=5source-pixel path-gap decrease each transition. No tuning after results.
Path proxy: segment along recorded direction, length=recorded HUD speed*0.4s (or missing=>unknown), gap=min visible boundary distance to segment minus HUD radius. This is screen-space stationary-surface proxy, NOT validated inertial trajectory/safety. Pair velocity is relative image motion, NOT world NPC velocity. Heading changes and missing camera evidence explicitly flagged.
Candidate gate: at least2independent runs with same-object-supported warning>=400ms before adverse event, all required walls known and a verified non-regressing alternative; no harm in successful-contact controls. Existing sample availability may fail this. Do not count repeated frames as runs; no label of true threat/false positive without evidence. If gate fails retain baseline and report exact missing observable; no new capture merely to inflate denominator.
