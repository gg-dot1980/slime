# claude-7 ～ claude-9：決策頻率、決策比對、小地圖白點偵測

2026-11-25（台灣時間）。分支 `ocr-claude`，接續 [claude-5](../claude-5/README.md)（96fd2a9）。只測 v2.13 與最新版 v2.22。全部為新檔案，或只改本分支新增的檔案。不是 OCR4 驗收，不部署 Sites。

## 結論

- **OCR 控制器 0/34 過關**：claude-7 6 局、claude-6 決策比對 4 局、claude-8 12 局、claude-9 12 局。
- **決策頻率不是主因**：
  - 控制器每次決策（截圖、辨識、規劃）只要 6～11ms。
  - 受限全知機器人改成每 200ms 決策一次，v2.13 仍長到 130、183、186。
  - claude-7 改成每 50ms 決策一次，體型沒有變大（57～95）。
- **決策品質差距小**：同一時刻控制器和受限全知機器人選同方向的比例是 27～34%，但後悔值中位只有 5～9。
- **找到一個嚴重的辨識錯誤**：小地圖白點偵測幾乎失效。畫面外平均有 6.5 個真實白點 NPC，原本的偵測器（`growMarkers`）平均只抓到 0.2 個。小 NPC 的點半徑只有 1.2px，反鋸齒後永遠達不到嚴格的白色範圍。所以 claude-3 到 claude-7 的「追畫面外白點」實際上幾乎沒有生效。新偵測器 `whiteDots` 修正後，偵測數和真實數一致：v2.13 是 5.9／5.7，v2.22 是 8.3／9.3。
- **修好之後**：claude-9 在 v2.13 每局吞 NPC 12～20 次，接近受限全知機器人的 14～22 次，但 150 秒時體型只有 46～140，機器人有 128～194。目前推測差在獵物大小和食物量：claude-9 吞的獵物中位只有 0.56R，42% 小於 0.5R；食物成長也從約 30 降到約 13～32。

## 候選

- **claude-7**：決策規則同 claude-6，只把決策間隔從 200ms 改成 50ms。
- **claude-8**：決策規則同 claude-6，但把小地圖白點換成新的 `whiteDots` 偵測器，紅點仍用原偵測器。偵測方式是把每個像素當成「背景 #203238 加上比例 a 的白點色 #d3eee1」，再用和覆蓋率無關的 R/G 增量比例判斷：白點約 0.95、視野框和玩家點約 0.68、紅點約 2.5。
  - 結果：吞 NPC 次數增加，但 4 次死亡中有 3 次發生在追邊緣裁切物件時，凶手是 1.46～4.28 倍的巨型 NPC。原因是白點變多，被裁切的巨型 NPC 附近常剛好有別的小白點。
- **claude-9**：claude-8 加上更嚴格的條件。邊緣裁切物件要改判為目標，6 個小地圖像素內（約 430 世界 px）必須沒有紅點，原本是 3 個像素。

## 新增的測試端工具

- **決策比對**（`OBSERVE=1`）：每次決策都用受限全知機器人的評分方式，在真實狀態下替 8 個方向打分，記錄一致率、後悔值，以及後悔值 >30 的案例。
- **受限全知機器人的決策間隔**：`ORACLE_MS`。
- **合成像素測試**：`check-ocr-claude.cjs` 新增 4 項 `whiteDots` 測試，包括 1.2px 反鋸齒白點、3px 白點，並確認紅點、視野框、玩家點不會被誤判。共 44 項。
