# claude-10：邊緣弓形推算半徑（v2.13 與最新版 v2.22）

2026-11-25（台灣時間）。分支 `ocr-claude`，接續 [claude-7](../claude-7/README.md)（79565f4）。全部為新檔案，或只改本分支新增的檔案。不是 OCR4 驗收，不部署 Sites。

## 結論

- **150 秒內過關 0/12**，但控制器創下目前最佳紀錄：v2.22 一局在 150 秒時體型 160，v2.13 一局 151。
- **v2.13**：6/6 撐到 150 秒，體型 83、124、72、122、70、151，中位約 103（claude-9 約 94）。
- **v2.22**：體型 88、160、93、65；另 2 局死亡，第 108 秒死時體型 117、第 129 秒死時體型 82。每局吞 NPC 中位 13.5 次（claude-9 是 9.5 次），接近受限全知機器人的 15～23 次。
- **安全性**：把致命 NPC 看成安全的次數仍為 0/574。

## 為什麼做這個

- **成長來源比較**：受限全知機器人新增了成長來源紀錄（`oracle-view-growth-noimages.jsonl`）。結果顯示，在 v2.22 它和 claude-9 的獵物比例（約 0.62R）、食物量都差不多，差別在吞的次數。在 v2.13，這次機器人的成績（57～108）和 claude-9 相近，加上先前各輪合計 9 局，中位約 130，隨機變異很大。
- **漏掉的獵物在哪裡**：claude-9 漏掉的獵物幾乎都在畫面邊緣，被裁切或部分在畫面外。小地圖上，畫面邊緣正是視野框的線，視野框畫在點的上面，會蓋住那些點，所以小地圖也幫不上忙。
- **做法**：只碰到一個螢幕邊緣的色塊是一個圓的弓形。用弦長 c 和深度 h 推算半徑 R=(c²/4+h²)/(2h)（h<c/2 時；否則 R=c/2），圓心在邊緣外 R−h 的位置。

## 推算的準確度（`segment-check-noimages.jsonl`，claude-9 各 1 局）

| | v2.13 | v2.22 |
|---|---|---|
| 比對到的裁切物件 | 48 | 52 |
| 推算半徑／真實半徑 中位（p10～p90） | 0.98（0.78～1.09） | 0.96（0.76～1.14） |
| 推算圓心誤差中位 | 9px | 15px |

因為偶爾會低估到約 0.76 倍，門檻刻意保守：

- **推算 ≤0.8R，且推算圓心 3 個小地圖像素內沒有紅點**：只當成前進目標，不當作碰撞物件。就算低估到 0.76 倍，真實值也只有約 1.05R，仍低於 1.08R 的致命門檻。完整進入畫面後，再由未裁切的規則判斷（那時半徑誤差約 3%）。
- **推算 ≥0.82R**：除了原本對裁切物件的致命處理，再以推算圓心、1.3 倍推算半徑加一個危險區。
- **碰到兩個邊緣（角落）或 UI 遮罩**：沒有推算值，維持原本一律致命的處理。
