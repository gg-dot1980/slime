# OCR 控制台 GUI 指南

`/ocr-gui-design` 是可直接開啟的獨立實驗室。這個研究分支的 `/ocr` 也提供同一套桌機介面。操作者應能在同一畫面選好遊戲和策略、開始一局，並同時看見遊戲、目前的動作及其原因。調查辨識或查閱舊版本時，再展開相應工具。

## 原始碼與本機啟動

| 維護內容 | 儲存庫檔案 |
| --- | --- |
| 畫面結構與樣式 | [src/ocr.html](../../src/ocr.html)、[src/ocr-console.css](../../src/ocr-console.css) |
| 啟停、版本切換、原生控制器讀值及操作紀錄 | [src/ocr-console-runtime.js](../../src/ocr-console-runtime.js) |
| 六個系列、策略修訂及公開證據連結 | [src/ocr-console-catalog.js](../../src/ocr-console-catalog.js) |
| 獨立入口的資源網址 | [src/ocr-gui-design/routes.mjs](../../src/ocr-gui-design/routes.mjs)。建置時為共用 HTML 與目錄產生獨立網址。 |
| 原生來源固定、建置與 HTTP 路由 | [scripts/build.mjs](../../scripts/build.mjs)、[src/worker.js](../../src/worker.js) |

從儲存庫根目錄執行 `npm run build`、`node scripts/check-ocr-index.mjs`，再用 `npm run dev` 啟動本機預覽，開啟 `http://localhost:4173/ocr-gui-design`。按 Ctrl+C 可關閉預覽。建置會產生包含控制器與遊戲的 `dist/server/index.js`。

獨立入口從 `/ocr-gui-design/` 讀取 `style.css`、`catalog.js` 和 `runtime.js`。Grow、Claude 與測試版原生頁位於同一前綴下的 `grow`、`claude`、`test`。其餘三個系列直接載入 `/ocr1`、`/ocr2`、`/ocr3`。兩個入口共用原生控制器與歷史資料。

## 版面與操作

| 區域 | 預設呈現 | 驗收重點 |
| --- | --- | --- |
| 本局控制 | 「遊戲版本」「策略系列」「策略版本」和「開始實驗／停止」 | 控制項附可見標籤。切換後，選單、狀態和遊戲必須指向同一組來源。 |
| 遊戲畫面 | 保留桌面左側主要空間給原生遊戲與 HUD | 讓遊戲依可用視野繪製，邊緣和小地圖保持可見。窄螢幕先排遊戲，接著排即時判斷。 |
| 即時判斷 | 右側列出移動方向、當前決策、體型、時間、判斷耗時及嘗試次數 | 方向要對得上已送出的按鍵。尚無讀值時顯示「—」或具體狀態。 |
| 辨識診斷 | 按需展開當前系列提供的辨識輸出 | OCR1 的平均辨識耗時列在此處，當前決策耗時留「—」。OCR2 只有文字回報，無診斷畫布。 |
| 說明與歷史 | 「目前策略說明」「所有策略紀錄」「操作說明」預設收合 | 「所有策略紀錄」可篩選系列、查閱修訂差異與公開來源。篩選只影響清單。 |
| 本頁實驗紀錄 | 按需查看本次開啟頁面後的操作 | 每次明確按「開始實驗」記一筆，保留當時設定與停止原因。重整即清除。原生重試可在同一筆操作內發生。 |

外觀集中在 `src/ocr-console.css`。沿用 `--bg`、`--panel` 的深藍底與 `--ink` 的淺色文字。`--violet` 用於主要動作，`--mint` 標示執行中、當前方向與鍵盤焦點，`--warn` 搭配錯誤文字。雙欄在 740 CSS px 以下（含）改為單欄，460 px 以下讓操作按鈕獨占一列。窄版可讀性和真機遊戲成績分開驗證。

操作使用原生 `button`、`select` 或 `details`／`summary`。Tab 可以從「跳到實驗工作區」前往設定與各區塊，焦點始終可見。狀態以文字回報，八向指示另附方向名稱。選單的方向鍵與收合區的 Enter、空白鍵由焦點所在控制項接收。即時變化的數字宜保持安靜，讓輔助技術優先朗讀開始、停止與錯誤。

## 選項、讀值與證據

| 名稱 | 代表的事物 | 資料來源 |
| --- | --- | --- |
| 遊戲版本 | 本局載入的規則與遊戲畫面，例如 v2.13 | 選定家族原生控制頁提供的版本 |
| 策略系列／策略版本 | 哪一套控制器讀畫面、如何判斷和送鍵 | 系列包括 Grow、Claude、OCR1、OCR2、OCR3 與 OCR 測試版。版本選項來自各自的原生控制頁。 |
| 歷史修訂 | 該家族某一次變更、當時的目的與可追溯來源 | 修訂目錄及相應公開文件。可執行性以原生控制器實際支援為準。 |
| 驗證結果 | 指定遊戲版本及策略在特定條件下的結果 | 可追溯的自然實戰、控制測試或離線回放紀錄，分別標示 |

例如「v2.22 × Grow49」同時指定遊戲與策略。「定位誤差（像素）」是回放量測。要顯示自然局的過關比例，須能核對遊戲版本、策略、過關局數、分母與公開來源。中止與未知照來源列明。缺少可公開核對的結果就標明範圍或缺值。重整頁面、切換版本或等待載入時，清掉上一局的數字、箭頭和診斷畫面。

即時資訊取自遊戲可見畫面、HUD 與控制器的實際回報。執行中的即時辨識供本機檢視。歷史連結只指向可公開查閱的文件、原始碼、封存或證據。私人終場圖、逐幀或逐局原始帳本、含像素的輸出與私人下載位置應留在原保管處。證據分類依[獨立測試與驗收](https://github.com/gg-dot1980/slime/blob/test/ocr-test/docs/ocr/TESTING.md)與 [GitHub 存放規則](https://github.com/gg-dot1980/slime/blob/test/ocr-test/docs/ocr/GITHUB-STORAGE.md)。

## 切換與停止

1. 選定家族後，從該家族原生控制頁取得遊戲與本局策略選項。沒有提供子策略的家族收起「策略版本」欄位。等遊戲版本與來源核對完成再開放開始操作。失敗時顯示原因和「重新載入控制器」。
2. 開始後，以目前這組遊戲和控制器為唯一即時來源。決策、診斷與按鍵狀態應能與同一畫面的遊戲進度相互核對。
3. 變更家族、遊戲或本局策略時，先停止舊控制、釋放按住的鍵，再載入新選擇。舊回呼或延遲到達的事件只能更新其所屬的遊戲。
4. 停止或將頁面切至背景時，停止送鍵並清除按下外觀。切回頁面應可檢查目前狀態，再由操作者決定何時開始。

## 新增家族或修訂

- 在 `src/ocr-console-catalog.js` 的 `families` 登錄唯一的 `id`、顯示 `label`、同源原生控制頁 `route` 與短 `description`。需要指定預設策略時，`defaultStrategy` 填原生選項值。用原生頁逐一核對遊戲版本、策略、開始／停止、HUD、決策與可選診斷。頁面結構不同時，在 `src/ocr-console-runtime.js` 完成對應。
- 在同一目錄的 `history` 新增一筆修訂。`id` 唯一，`family` 對應已登錄家族，`version`、`label` 和 `title` 讓讀者能辨認修訂，`description` 簡述行為變更。`url`、`sourceUrl`、`archiveUrl`、`evidenceUrl` 只填有對應資料的公開位置，`evidence` 用文字寫明驗證種類與範圍。
- 只新增舊版紀錄時，更新歷史目錄即可。若要提供「選用此策略」，`strategyValue` 要逐字對應原生 `option.value`。例如 Grow49 這筆的 `id` 為 `grow-49`，原生值為 `grow-23`。維護時須核對原生頁上該選項的標籤與值，再實測開始、切換與停止。只有文件或封存的修訂保留查閱連結。
- 替換可執行來源時一併核對 `scripts/build.mjs`。Grow 固定使用 Grow49，建置時以固定的 SHA-256 同時核對候選登錄與 HTML。改用下一版時，請一起更新來源、雜湊、路由檢查及目錄中的原生策略對應。Claude 取固定提交的 `src/ocr-claude.html` 並填入隔離遊戲。修訂目錄中的版本說明與公開連結應對應此次實際供應的來源。

## 介面驗收

完成本機建置與路由檢查後，在 `/ocr-gui-design` 進行以下操作，並抽查原入口 `/ocr`。

- [ ] 從實驗室網址直接開啟，確認桌面首屏能選遊戲與策略，看見遊戲、主要決策與啟停操作。縮至手機寬度時逐區可讀，操控區沒有整頁橫向溢出。
- [ ] 每個家族至少核對一組原生遊戲與策略。沒有複數選項或某項讀值的來源，依其實際能力顯示。
- [ ] 啟動一局，比對原生 HUD、動作／理由及方向鍵。停止、切至背景、運行中換家族／遊戲／策略後，都確認舊鍵已放開、舊狀態已清除。
- [ ] 先後以不同設定開始兩次，核對「本頁實驗紀錄」保留兩筆及各自的停止原因。重新整理後應顯示空狀態，所有策略的公開修訂仍可查閱。
- [ ] 以 Tab 操作選擇、開始／停止與收合區。焦點可見，操作選單及歷史區時，鍵盤輸入不會移動遊戲角色。
- [ ] 展開辨識診斷、收起再展開，確認資料屬於當前來源。長篇說明初次開啟時保持收合。
- [ ] 各家族最早與最新的已收錄修訂可找到。抽查一筆只有文件的舊版及一筆有原始碼／結果的修訂，核對各連結目的地、證據種類與公開範圍。
